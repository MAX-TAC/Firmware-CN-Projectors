# ET32: вывод по качеству Android, APK и вендорских служб

Источник: модифицированный YG_6M046.bin. Анализ 17 APK, 8 нативных программ, Android 9 system/vendor, разметки MStar, shell-скриптов, конфигураций. Статический разбор, без запуска на физическом устройстве. Выводы НЕ следует автоматически переносить на FlixTone D11 Master.

## Главный вердикт
- Аппаратные функции структурно отделены от пользовательского интерфейса. В системе есть Binder-служба трапеции с клиентской библиотекой, Java API MediaTek и конфигурации фокусировки/клавиш. Это полезно для собственной оболочки.
- Интеграция и безопасность пользовательской прошивки выполнены неаккуратно. Старый Android 9, патч безопасности 2021-01-05, userdebug, dev-keys, ro.adb.secure=0, запрос permissive SELinux. Build fingerprint с Android 4.4.4 при фактическом Android 9.
- Встроенный Boa должен был запускаться в составе main-процессов, как root, на HTTP 80, без Listen-ограничения на конкретный интерфейс. CGI test.cgi отдаёт в браузер системные переменные окружения, метод запроса, query string и результат id. Есть возможная утечка диагностики при доступности устройства по сети. Нет тестов достижимости порта на живом ET32.
- Скрипт trapezoid_save.sh устанавливает права 777 на файл /data/trapezoid/trapezoidcorrect_points_offset.ini. Исправлять права надо после проверки механизма сохранения.
- NewLinkService и AutoPair заявляют одинаковый package name com.newlink.service, хотя размещены отдельно. Это потенциальный конфликт пакетов: проверить что реально устанавливает PackageManager, какие подписи и версии.
- Часть системных компонентов экспортирована без явного manifest permission. Это поверхность для проверки авторизации на уровне Binder/Intent, но НЕ доказательство отсутствия проверок внутри кода.

## Подтверждённые интерфейсы фокусировки и трапеции
- APK включают API MediaTek MtkTvFApiCustom с методами setFocusMotor и идентификаторами операций автофокуса/автокейстоуна в диапазоне 61720–61728.
- В native trapezoidTest встречаются методы TrapezoidClient для установки углов, поворота, координат, сохранения сетки и режима геометрической коррекции.
- Именно эти API разумно оборачивать в собственный ProjectorControlService. Моторы, вычисление изображения, видеотракт и TEE следует оставить в исправно работающем нижнем слое, пока нет исходников.

## Что реально улучшить
1. Проверить на устройстве active service/ports/uid, keyevents, фактический SELinux, установленный вариант дублирующегося пакета, сценарий восстановления из неудачной прошивки.
2. Отключить необязательные CGI, заводские утилиты и магазин, устранить 777, убрать лишние exported и опасные привилегии.
3. Перенести фокус/трапецию/пульт/HDMI в единый проверяемый привилегированный адаптер к существующим MediaTek/Binder API.
4. Поверх адаптера сделать собственное Android TV меню, настройки и launcher.
5. Только после стабилизации на базовой ОС оценивать совместимость с Android 13/15; без BSP, HAL, 32-битных библиотек и совместимого ядра перенос не гарантируется.

## Уверенность и ограничения
В ряде JADX-декомпиляций есть ошибки в отдельных классах, а в некоторых компактных APK исходный функциональный код не восстановлен (виден один Java-файл). Подсчёт Java-паттернов включает библиотеки из APK и не доказывает качество пользовательского кода. SELinux bootargs, root HTTP и weak ADB свойства определены статически, фактическую работу надо проверить на устройстве. Наличие hostnames www.newlinksz.com/baidu не доказывает отправку персональных данных. Google Play Services и Widevine в составе образа не доказывают официальную сертификацию.

Итог: аппаратная архитектура имеет неплохую основу для переписывания UI, но поддержка, сборка и безопасность конечной прошивки слабые. Новая UI-прошивка на существующем Android реалистична; чистый Android TV 13/15 со старыми BSP и драйверами без серьёзного портирования малореалистичен.
